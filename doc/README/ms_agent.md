\# 汐岸小筑民宿前台业务问答助手知识库



\## 0. 知识库说明



\### 适用范围



本知识库仅用于回答汐岸小筑微信小程序前台用户的业务问题，覆盖游客和已登录普通用户的浏览、搜索、收藏、购物车、预订、订单及评价业务。



本知识库不包含后台管理、管理员账号、内部接口地址、数据库、部署、开发调试或运营审批操作。用户询问后台操作时，应回复：“该问题属于平台运营管理范围，请联系平台工作人员处理。”



\### 版本信息



\- 适用产品：汐岸小筑旅游民宿平台

\- 适用版本：V1.2

\- 整理日期：2026-09-29

\- 版本状态：V1.2 已回归通过，可交付



\### 回答原则



1\. 只依据本知识库中明确记录的业务规则回答，不推测未说明的政策。

2\. 房价、库存、房态、上下架状态和订单状态属于实时数据，应以用户当前页面显示及系统最终校验结果为准。

3\. 不承诺未明确规定的退款到账时间、取消费用、发票、押金、早餐、宠物、儿童、停车、接送、入住时刻或退房时刻。

4\. 不向用户透露其他用户的资料、收藏、购物车、订单或评价信息。

5\. 不向用户提供管理员账号、内部权限、接口、数据库或系统配置等信息。

6\. 页面显示与服务端校验不一致时，以服务端最终校验结果为准，并建议用户刷新页面后重试。



\## 一、账号、登录与权限



\### 游客可使用的功能



未登录游客可以浏览首页、民宿列表、民宿详情、房型列表、房型详情、搜索结果、推荐房型、房态和已审核通过的评价。



\### 必须登录的功能



收藏、取消收藏、查看收藏、加入购物车、修改购物车、创建订单、查看订单、取消订单、提交评价和管理个人资料前必须登录。



\### 微信登录规则



用户通过微信登录使用小程序。首次登录会创建用户账号，后续使用同一微信身份登录不会重复创建账号。



登录前需要同意相关用户协议或授权要求；未同意时不能完成登录。



登录凭证失效或账号不可用时，受保护功能无法继续使用。此时应提示用户重新登录；普通用户登录凭证默认有效期为 7 天。



\### 个人资料规则



已登录用户可以维护本人的昵称、头像、性别、生日、手机号和邮箱等资料。生日采用“年-月-日”格式。



用户只能查看和操作自己的个人资料、收藏、购物车、订单和评价，不能读取、修改或删除其他用户的数据。



\## 二、前台入口与页面导航



\### 底部导航



当前小程序底部导航为：首页、民宿、购物车、我的。



\### 订单入口



订单列表不在底部导航中。用户可进入“我的”，再点击“我的订单”查看订单。



\### 资讯功能



当前版本不提供旅游资讯模块，首页没有资讯入口。遇到资讯、文章或新闻相关问题时，应说明该功能不在当前版本范围内。



\## 三、首页、民宿与房型浏览



\### 首页内容



首页展示轮播图、推荐民宿和“为你推荐”的推荐房型。



推荐房型卡片展示房型名称、所属民宿名称、价格和封面图。点击房型卡片进入对应房型详情。



“为你推荐”有数据时，标题右侧显示“查看更多 >”。点击后进入“全部房型”页面。



\### 民宿浏览路径



用户可从底部“民宿”进入民宿列表。点击某家民宿后进入民宿详情，再查看该民宿的房型。



民宿内房型页显示该民宿的头部信息，并且只展示该民宿当前可售的房型。



\### 全部房型



“全部房型”页面展示所有民宿当前可售的房型，不展示某一家民宿的专属头部信息。每张房型卡片都会显示所属民宿名称。



全部房型单次最多展示 50 条，不提供分页按钮、触底加载或“加载更多”。



\### 可售房型规则



房型只有同时满足以下条件，才属于前台可售房型：



\- 房型已经上架；

\- 房型所属民宿已经上架；

\- 房型库存大于 0。



房型下架、所属民宿下架或库存变为 0 后，前台不应继续展示或允许下单。



\### 图片规则



房型图片无法加载时，页面使用项目内置占位图。图片失败不会隐藏房型卡片，也不会影响用户进入详情查看文字信息。



\## 四、搜索与推荐



\### 搜索范围



首页搜索支持以下关键词：



\- 民宿名称；

\- 民宿地点或地址；

\- 房型名称。



搜索结果会区分民宿和房型。点击民宿结果进入民宿详情，点击房型结果进入房型详情。



搜索到的房型仍必须满足可售房型规则。



\### 推荐规则



推荐房型优先参考订单、收藏和热度等用户行为。未登录或用户行为不足时，系统返回当前可售的热门房型。



推荐结果只包含已上架民宿下、已上架且有库存的房型。



\## 五、房态、入住日期与离店日期



\### 日期基本规则



入住日期不得早于当天，离店日期必须晚于入住日期。



预订日期不得超过未来 365 天，单笔订单最多连续入住 60 晚。



\### 房态与库存



系统会按所选日期检查每日房态和库存。即使房型列表显示有库存，创建订单时仍需重新校验所选日期是否可订。



房型已下架、所属民宿已下架、库存不足、房态不可用或日期存在冲突时，系统会拒绝加入购物车或下单。



\### 实时变化



房价、库存和房态可能发生实时变化。用户应以创建订单时系统确认的结果为准，问答助手不能保证某一房型在未来某个时间一定可订。



\## 六、收藏



\### 收藏规则



登录用户可以收藏当前可售房型、取消收藏和查看自己的收藏列表。



同一用户不能重复收藏同一房型。重复收藏时，系统会提示该房型已收藏，而不会新增重复记录。



只有房型上架、所属民宿上架且库存大于 0 时才能收藏。



\### 收藏数据权限



用户只能查看和操作自己的收藏，不能查看或修改其他用户的收藏。



\### 收藏列表范围



收藏列表不提供分页、触底加载或批量操作。



\## 七、购物车



\### 加入购物车



登录用户可以选择房型、入住日期和离店日期后加入购物车。未登录用户需要先登录。



加入购物车时会校验房型和民宿是否上架、库存、房态以及入住和离店日期。



\### 重复加购规则



同一用户、同一房型和同一入住日期不能重复加入购物车。重复添加时，应明确提示“该日期的房型已在购物车中”或含义相同的提示，不应笼统提示网络错误。



\### 房间数量规则



购物车中的一条记录对应一间房。当前版本不提供房间数量修改，也不支持把同一房型的多间房合并为一笔订单。



用户如需预订多个不同购物车项目，可以使用购物车批量结算；单次最多结算 10 项，每一项分别生成一笔订单。



\### 修改与删除



用户可以修改购物车项目的入住日期和离店日期。修改后的日期仍必须符合预订日期、入住晚数、库存和房态规则。



用户可以移除单个购物车项目，也可以清空自己的购物车。



批量创建订单时，只有成功下单的购物车项目会被删除；下单失败的项目会继续保留。



\### 购物车列表范围



购物车列表不提供分页、触底加载、房间数量调整或批量删除功能。



\## 八、创建订单与金额



\### 创建订单入口



用户可以从房型详情直接预订，也可以从购物车结算并创建订单。



\### 创建订单所需信息



创建订单时需要提供房型、入住日期、离店日期、联系人姓名和联系电话。备注为可选内容，最多 200 个字符。



\### 订单金额规则



订单中的房型名称、房型图片、入住晚数、单价、总价、实际金额和订单号均由系统根据实时房型及日期数据生成。



用户页面提交的价格不能作为最终价格依据。最终价格和金额以系统创建订单时的计算结果为准。



\### 下单校验



创建订单时，系统会再次校验：



\- 用户是否已登录；

\- 房型及所属民宿是否上架；

\- 所选日期是否合法；

\- 入住晚数是否在 1 至 60 晚范围内；

\- 是否超过未来 365 天；

\- 每日房态和库存是否可用；

\- 是否存在不能重复预订的日期冲突。



任一条件不满足时，订单不会创建。



\### 批量结算



购物车单次最多结算 10 项。每个购物车项目对应一间房和一笔独立订单，不会合并为一笔多房间订单。



\## 九、支付、订单状态与取消



\### 支付能力说明



当前版本没有接入真实微信支付。页面中的支付处理属于系统现有的模拟流程，不会发起真实微信支付扣款。



\### 订单状态



| 状态 | 前台名称       | 用户可理解的含义                     |

| ---- | -------------- | ------------------------------------ |

| 0    | 待支付         | 订单已创建，等待当前版本的支付处理。 |

| 1    | 已支付／已确认 | 当前版本的支付或确认处理已完成。     |

| 2    | 入住中         | 已由工作人员办理入住，用户正在入住。 |

| 3    | 已完成         | 订单已经完成，可以按规则提交评价。   |

| 4    | 已取消         | 订单已经取消，不能继续入住。         |

| 5    | 已退款         | 订单已进入退款完成状态。             |



\### 状态流转



正常状态流转为：待支付 → 已支付／已确认 → 入住中 → 已完成。



待支付或已支付／已确认状态可以转为已取消。其他状态不能由用户自行取消。



用户只能对自己的待支付订单执行当前版本的支付处理。办理入住和完成订单由民宿工作人员处理。



\### 查看订单



用户可通过“我的 → 我的订单”查看自己的订单列表和订单详情。用户不能查看其他用户的订单。



\### 取消订单



用户只能取消属于自己的待支付或已支付／已确认订单。订单处于入住中、已完成、已取消或已退款状态时，不能再取消。



当前资料没有规定取消费用、免费取消截止时间、退款比例或退款到账时间。遇到这些问题时，不得自行承诺，应提示用户联系民宿工作人员，并以具体订单处理结果为准。



\## 十、评价



\### 可评价条件



用户只能评价属于自己的已完成订单，并且同一订单只能提交一条评价。订单未完成、已评价或不属于当前用户时不能提交评价。



\### 评价内容



评价评分为 1 至 5 分，文字内容为 1 至 500 个字符，可以附带图片。



\### 审核与公开展示



用户提交评价后需要经过平台审核。只有审核通过的评价会在民宿或房型前台公开展示。



评价暂未公开不代表提交失败，也可能是仍在审核中或已被驳回。



\### 修改和删除



只有审核驳回的评价可以修改。修改后会重新进入待审核状态。



用户可以删除自己的评价，不能修改或删除其他用户的评价。



\## 十一、列表、空态和异常提示



\### 列表加载方式



当前版本的民宿、房型、收藏和购物车列表采用一次性加载，不提供分页控件、触底加载或“加载更多”。



\### 无数据



接口请求成功但没有符合条件的数据时，页面应显示对应空态，例如“暂无可售房型”或“购物车为空”。



\### 请求失败



网络或接口请求失败时，应显示加载失败和重试提示，不能把请求失败误报为“暂无数据”。



\### 图片失败



图片加载失败时使用内置占位图，保留房型文字信息和点击能力。



\### 资源失效



用户打开详情前，如果房型或所属民宿已经下架、库存变为 0 或资源不存在，应提示“资源已不可用”或含义相同的提示，并阻止继续下单。



\### 常见业务错误解释



| 场景                 | 应向用户说明的含义                                   |

| -------------------- | ---------------------------------------------------- |

| 请先登录／登录已过期 | 当前操作需要登录，请重新登录后再试。                 |

| 参数或日期错误       | 检查入住日期、离店日期、入住晚数及填写内容。         |

| 权限不足             | 当前用户无权查看或操作该数据，通常是资源不属于本人。 |

| 资源不存在或已下架   | 民宿或房型已不可用，不能继续预订。                   |

| 重复收藏             | 该房型已经收藏，无需重复添加。                       |

| 重复加购             | 同一入住日期的该房型已经在购物车中。                 |

| 库存或日期冲突       | 所选日期当前不可订，请更换日期或其他房型。           |

| 服务异常             | 建议稍后重试；持续失败时联系平台工作人员。           |



\## 十二、当前版本不支持的前台能力



以下能力不属于 V1.2，问答助手不能回答为“可以使用”：



\- 真实微信支付；

\- 一笔订单预订同一房型的多间房；

\- 修改购物车房间数量；

\- 收藏和购物车批量操作；

\- 民宿、房型、收藏和购物车列表分页或触底加载；

\- 旅游资讯或新闻功能。



\## 十三、常见问题标准答案



\### 不登录可以看民宿和房型吗？



可以。游客可以浏览首页、民宿、房型、搜索结果、推荐房型、房态和已审核评价。收藏、加入购物车、下单、查看订单和评价需要先登录。



\### 为什么房型突然找不到了？



房型可能已下架、所属民宿已下架、库存已变为 0，或者资源已经失效。请刷新页面查看当前可售房型，以系统实时结果为准。



\### 为什么列表显示有房，下单时却提示不可订？



列表库存和房态可能实时变化。创建订单时系统会按所选日期重新校验每日库存、房态和订单冲突，最终以下单时的校验结果为准。



\### 最早可以预订哪一天？



入住日期最早为当天，不能选择早于当天的日期。



\### 最远可以预订到什么时候？



入住和离店日期不能超过未来 365 天，单笔订单最多入住 60 晚。



\### 为什么不能重复加入购物车？



同一用户、同一房型和同一入住日期只能保留一条购物车记录。如果已经添加过，系统会拒绝重复添加。



\### 可以一次订多间房吗？



一笔订单只对应一间房，不能修改房间数量。购物车可以一次结算最多 10 个项目，但每个项目会分别生成一笔订单。



\### 在哪里查看订单？



进入“我的”，点击“我的订单”即可查看订单列表和详情。



\### 哪些订单可以取消？



只有本人处于待支付或已支付／已确认状态的订单可以取消。入住中、已完成、已取消或已退款订单不能再取消。



\### 取消订单会扣费吗？多久退款？



当前规则没有说明取消费用、退款比例或退款到账时间。请联系民宿工作人员确认，并以具体订单处理结果为准。



\### 为什么我的评价没有公开显示？



评价提交后需要审核，只有审核通过的评价会公开展示。评价可能仍在审核中，或者已被驳回。



\### 被驳回的评价可以修改吗？



可以。只有审核驳回的评价可以修改，修改后会重新进入待审核状态。



\### 小程序支持真实微信支付吗？



当前版本未接入真实微信支付，支付相关操作属于系统模拟流程，不会发起真实微信支付扣款。



\## 十四、兜底与转人工规则



\### 知识库未明确的问题



如果用户咨询以下事项，而具体民宿页面或订单中也没有明确说明，应回复：“当前资料没有明确说明该规则，请联系民宿工作人员确认，并以实际民宿或订单政策为准。”



典型事项包括：



\- 具体入住和退房时刻；

\- 押金及退还方式；

\- 发票开具；

\- 早餐、停车、接送、加床；

\- 儿童、宠物和访客政策；

\- 取消费用、退款比例和退款到账时间；

\- 特殊证件、入住人变更或线下服务要求。



\### 实时房源问题



用户询问某房型具体价格、某日是否有房或剩余数量时，应引导用户打开对应房型并选择日期查询，不能依据历史信息作保证。



\### 账号或订单异常



用户重新登录、刷新页面和重试后仍无法操作时，应建议联系平台工作人员，并提供订单号、发生时间和页面提示。不得要求用户提供登录密码或完整身份敏感信息。



\### 投诉、纠纷和法律问题



问答助手不作法律结论。建议用户保留订单、支付记录、聊天记录和页面截图，并联系平台工作人员处理；需要法律帮助时，通过合法渠道咨询专业机构。
