# 汐岸小筑旅游民宿平台产品需求文档

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 产品名称 | 汐岸小筑旅游民宿平台 |
| 所属行业 | 旅游住宿行业（民宿预订与运营管理） |
| 产品形态 | 微信小程序 + Vue 管理后台 + Spring Boot 后端 |
| 当前产品版本 | V1.2 |
| 更新日期 | 2026-09-28 |
| 当前状态 | V1.2 已回归通过，可交付 |

## 2. 产品概述

本产品为民宿预订与运营管理平台。普通用户通过微信小程序浏览民宿和房型、搜索可售房源、收藏、加入购物车、预订并评价；管理员通过后台维护民宿、房型、订单、评价和用户信息。

产品目标：

1. 让用户以“民宿 → 房型”的清晰路径完成浏览和预订。
2. 支持首页推荐、搜索和民宿列表三种房源发现路径。
3. 让运营人员安全维护房源、订单和评价数据。
4. 保证用户数据、订单数据和后台操作的服务端权限校验。

## 3. 用户与权限

### 3.1 未登录访客

可浏览首页、民宿、房型、搜索结果及已审核评价；收藏、购物车、下单、取消订单和评价前必须登录。

### 3.2 普通用户

通过微信登录使用小程序。用户仅可访问和操作自己的资料、收藏、购物车、订单及评价。

### 3.3 管理员

通过管理后台维护民宿、房型、订单、评价和用户数据，查看经营看板。管理员权限必须由服务端校验，不能仅依赖前端页面控制。

## 4. 产品范围

### 4.1 已交付范围

- 微信登录、用户资料管理与身份鉴权。
- 民宿列表、民宿详情、房型列表、房型详情、房态和已审核评价浏览。
- 民宿名称、地点和房型名称关键词搜索。
- 首页推荐民宿、推荐房型，以及“为你推荐 → 查看更多 → 全部房型”路径。
- 收藏、购物车、创建订单、订单查询与取消、评价提交和后台审核。
- 后台数据看板、民宿管理、房型管理、订单管理、评价审核、用户管理和图片上传。

### 4.2 不在当前版本范围内

- 资讯模块及其小程序入口、后台维护能力已移除。
- 不接入真实微信支付；支付相关流程按当前系统既有模拟规则执行。
- 不提供多间同房型合并下单或购物车房间数量修改；一笔订单对应一间房。
- 小程序端民宿、房型、收藏和购物车列表不采用分页、触底加载或“加载更多”。
- 购物车、收藏和后台各管理模块的批量操作不纳入 V1.2，计划作为 V1.3“批量操作能力”需求包统一评审。

## 5. 核心业务流程

```text
微信登录
  → 首页推荐 / 搜索 / 民宿列表
  → 民宿详情
  → 该民宿的房型列表
  → 房型详情
  → 收藏、加入购物车或直接预订
  → 创建订单
  → 查询、取消或完成订单
  → 提交评价
  → 管理员审核评价
```

```text
管理员登录
  → 查看经营看板
  → 维护民宿、房型、图片和上下架状态
  → 查看及处理订单
  → 审核评价
  → 管理用户
```

## 6. 功能需求

### 6.1 首页、民宿与房型浏览

1. 首页展示轮播图、推荐民宿和“为你推荐”的推荐房型。
2. 首页不展示资讯模块，也不保留资讯入口；底部导航包含首页、民宿、订单和我的。
3. 点击“民宿”进入民宿列表；点击某家民宿后，才进入该民宿的房型列表。
4. 民宿内房型页显示所属民宿头部信息，仅展示该民宿的可售房型。
5. 首页“为你推荐”有数据时显示“查看更多 >”；点击后进入“全部房型”页。
6. 全部房型页展示所有可售房型，每张卡片展示所属民宿名称；不展示某一家民宿的头部信息。
7. 小程序端列表采用一次性完整加载，不展示分页控件、触底加载或“加载更多”。全部房型单次返回最多 50 条。

可售房型必须同时满足：房型已上架、所属民宿已上架、库存大于 0。房型或民宿下架后，前台不得继续展示或下单。

### 6.2 搜索与推荐

1. 首页搜索支持民宿名称、地点和房型名称关键词。
2. 搜索结果明确区分民宿和房型；点击民宿进入民宿详情，点击房型进入房型详情。
3. 推荐房型展示房型名称、所属民宿名称、价格和封面图。
4. 推荐优先参考订单、收藏和热度等行为；未登录或行为不足时返回可售热门房型。
5. 图片不可用时展示项目内置占位图，不隐藏房型卡片或阻断进入详情。

### 6.3 登录、资料与数据权限

1. 小程序使用微信登录获取身份；首次登录自动创建用户，重复登录不得重复创建。
2. 登录后返回 Token、用户 ID 和基础资料；受保护接口必须验证有效 Token。
3. 用户可维护本人昵称、头像、性别、生日、手机号和邮箱等资料。
4. 用户不得读取、修改或删除其他用户的收藏、购物车、订单、评价或资料。

### 6.4 收藏与购物车

1. 用户可收藏、取消收藏和查看自己的收藏房型；同一用户不得重复收藏同一房型。
2. 用户可将房型及入住、离店日期加入购物车，也可移除或清空自己的购物车。
3. 入住日期和离店日期必须合法，离店日期必须晚于入住日期。
4. 同一用户、同一房型和同一入住日期不得重复加入购物车。
5. 购物车中的单条记录对应一间房，不提供房间数量修改；可按既有规则调整入住和离店日期。

### 6.5 订单

1. 用户可从房型详情或购物车创建订单。
2. 订单保存房型、入住日期、离店日期、晚数、单价、总价、联系人、备注及下单快照。
3. 用户可查看自己的订单和订单详情，并仅能在允许状态下取消订单。
4. 管理员可查看全部订单、查看详情并按业务规则处理订单状态。
5. 创建订单、更新状态、取消订单及库存等关键规则均以服务端校验为准；前端限制不能替代服务端校验。

| 状态 | 名称 | 说明 |
| --- | --- | --- |
| 0 | 待支付 | 订单已创建，等待当前版本的支付处理。 |
| 1 | 已支付 | 已完成支付处理。 |
| 2 | 入住中 | 用户正在入住。 |
| 3 | 已完成 | 订单完成，可提交评价。 |
| 4 | 已取消 | 订单被用户或管理员取消。 |
| 5 | 已退款 | 订单已退款。 |

### 6.6 评价与审核

1. 用户可对满足业务条件且属于自己的订单提交一条评价。
2. 评价包含 1–5 分评分、文字内容和可选图片。
3. 管理员审核评价；前台仅展示审核通过的评价。
4. 被拒绝的评价可修改后重新提交；用户仅能删除自己的评价。

### 6.7 管理后台与图片上传

1. 后台提供经营看板，以及民宿、房型、订单、评价和用户管理。
2. 管理员可维护民宿和房型的基础信息、价格、库存、设施、图片及上下架状态。
3. 图片上传支持 jpg、png、webp，单文件不超过 5MB，使用唯一文件名避免覆盖。
4. 上传文件必须保存到本项目的后端上传目录，并通过项目配置的图片访问路径提供访问；不得在用户本地磁盘中另建与项目无关的目录。
5. 批量删除、批量上下架、批量审核等能力不属于 V1.2。

## 7. 非功能与异常要求

### 7.1 安全与数据一致性

- 登录态、用户归属和管理员权限均由服务端校验。
- 非法参数、越权访问、重复收藏、重复加购和非法订单状态流转必须被拒绝并返回明确提示。
- 敏感配置不得写入公开代码或文档。

### 7.2 页面与兼容性

- 常见手机屏幕上应能正常展示小程序核心页面。
- 无数据、网络/接口失败和图片失败必须分别展示正确的空态、重试提示或占位图，不得白屏或将请求失败误报为无数据。
- 房型或所属民宿在进入详情前下架时，应提示资源不可用并阻止继续下单。

### 7.3 性能

- 核心浏览、搜索、下单、订单查询和后台管理接口应在当前部署数据量下稳定响应。
- 小程序端房源相关列表采用受控的一次性加载；全部房型接口单次返回量不超过 50 条。
- 订单创建、权限隔离、库存及状态流转是性能和回归测试重点。

## 8. 验收状态与后续规划

### 8.1 V1.2 验收结论

V1.2 已完成“为你推荐”查看更多与全部可售房型浏览能力。回归测试已通过，未发现功能、界面、接口或回归问题；当前版本可交付。

### 8.2 V1.3 候选需求

后续对以下能力统一评审、排序和验收，不得作为 V1.2 的临时修复插入：

- 购物车、收藏的批量操作。
- 后台民宿、房型、订单、评价和用户模块的批量操作。

是否实施及具体交互方式，应结合实际运营数据量与使用频率确定。
