# 民宿微信小程序及后台管理系统接口文档

> 文档版本：V1.1  
> 更新日期：2026-09-18  
> 适用范围：微信小程序、后台管理端、Spring Boot 后端  
> 依据：当前 V1.1 Controller、DTO、鉴权拦截器及前端调用代码

## 1. V1.1 接口变更摘要

与 V1.0 文档相比，V1.1 有以下主要变化：

1. 分页参数统一为从 `1` 开始，默认 `page=1&size=10`，服务端最大 `size=50`。
2. 用户和管理员 Token 改为签名 JWT，推荐请求头为 `Authorization: Bearer <token>`。
3. 增加统一权限拦截：用户接口、管理员接口及登录接口按角色隔离，鉴权失败使用 HTTP `401/403`。
4. `POST /user/login` 已停用并返回 `410`，微信登录统一使用 `POST /user/wxlogin`，请求体必须包含 `agreed=true`。
5. 民宿公开列表只返回已上架数据；管理员携带 Token 时可查询全部或按状态筛选。
6. 房型公开列表必须携带 `homestayId`，只返回已上架、库存大于 0 且所属民宿已上架的房型。
7. 新增 `GET /room/search`；`GET /room/count/{homestayId}` 调整为管理员接口。
8. 创建订单时，房型名称、价格、晚数、金额和订单号全部由服务端生成，客户端不得提交价格作为可信数据。
9. 订单日期限制为当天至未来 365 天，单次入住最多 60 晚，批量下单最多 10 个房型。
10. 订单状态更新支持 JSON 请求体和查询参数；确认、入住、完成由管理员办理，用户仅能支付自己的待支付订单。
11. 新增购物车日期修改接口 `PUT /cart/{id}`。
12. 评价仅允许已完成订单提交；只有审核驳回的评价可修改，修改后重新变为待审核。
13. 图片上传改为管理员接口，支持 JPG/JPEG、PNG、WEBP，最大 5 MB。
14. 资讯模块已从 V1.1 后端移除，原 `/news/**` 接口不再可用。

## 2. 服务地址与本地调试

### 2.1 后端地址

```text
http://127.0.0.1:8082
```

`localhost:8082` 在浏览器中通常也可使用。微信开发者工具统一使用 `127.0.0.1`，避免 `localhost` 被解析到不可用的 IPv6 或代理地址。

### 2.2 民宿列表为空时的检查顺序

1. 确认 Spring Boot 后端已经启动，并监听 `8082` 端口。
2. 浏览器访问：

   ```text
   http://127.0.0.1:8082/homestay/list?page=1&size=10
   ```

3. 正常响应应满足 `code=200` 且 `data.list` 有数据。
4. 微信开发者工具本地调试时确认“详情 → 本地设置 → 不校验合法域名”已启用。
5. 真机调试不能使用 `127.0.0.1`，应改为开发电脑局域网 IP，或使用已备案的 HTTPS 域名。

### 2.3 后台管理端口与代理

本地开发时，后台管理前端和后端 API 使用不同端口：

| 服务 | 端口 | 本地访问地址 | 用途 |
| --- | --- | --- | --- |
| 后台管理前端（Vue） | `9532` | `http://localhost:9532` | 浏览器打开后台管理页面。该端口由 `frontend/admin/vue.config.js` 的开发服务器配置。 |
| Spring Boot 后端 API | `8082` | `http://127.0.0.1:8082` | 提供登录、民宿、房型、订单等接口，不是后台管理页面端口。 |

因此，开发人员应在浏览器访问 `http://localhost:9532` 使用后台管理系统；后台页面发出的接口请求再由 Vue 开发服务器代理到 `8082` 后端。若 `9532` 可以打开但页面提示接口错误，应检查 `8082` 后端是否已启动。

后台 Axios 使用 `/api` 作为前缀，`vue.config.js` 会移除该前缀并转发到后端。例如：

```text
前端 /api/order/list  ->  后端 http://127.0.0.1:8082/order/list
```

管理员 Controller 自身路径包含 `/api/admin`，因此登录请求为：

```text
前端 /api/api/admin/login  ->  后端 /api/admin/login
```

当前管理端代码已经按上述代理规则调用。

## 3. 通用约定

| 项目 | V1.1 约定 |
| --- | --- |
| 数据格式 | JSON；上传使用 `multipart/form-data` |
| 字符编码 | UTF-8 |
| 分页 | `page` 从 1 开始，默认 1；`size` 默认 10、最大 50 |
| 日期 | `yyyy-MM-dd` |
| 日期时间 | `yyyy-MM-dd HH:mm:ss` |
| 金额 | JSON 数字，服务端使用 `BigDecimal` |
| 通用响应 | `{ code, msg, data }` |

成功响应示例：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {}
}
```

分页响应示例：

```json
{
  "code": 200,
  "msg": "获取成功",
  "data": {
    "list": [],
    "total": 0,
    "page": 1,
    "size": 10
  }
}
```

常用状态码：

| HTTP/code | 含义 |
| --- | --- |
| 200 | 成功 |
| 400 | 参数格式或业务输入错误 |
| 401 | 未登录、Token 无效或已过期 |
| 403 | 角色或资源权限不足 |
| 404 | 资源不存在或公开资源已下架 |
| 409 | 状态冲突、重复提交、库存或日期冲突 |
| 410 | 旧接口已停用 |
| 500 | 服务端异常 |

说明：权限拦截和全局异常使用真实 HTTP 状态；部分 Controller 内部业务判断仍可能返回 HTTP 200，但 JSON `code` 为错误码。调用方应同时判断 HTTP 状态和响应体 `code`。

## 4. 鉴权

### 4.1 请求头

推荐写法：

```http
Authorization: Bearer <JWT>
```

为兼容旧前端，也支持：

```http
token: <JWT>
```

### 4.2 角色

| 角色 | 说明 |
| --- | --- |
| USER | 微信小程序用户 |
| ADMIN | 后台管理员 |

JWT 中包含主体 ID、角色、签发时间和过期时间。用户 Token 默认有效期 7 天，管理员 Token 默认有效期 8 小时。服务端还会检查对应用户/管理员是否存在且状态为启用。

### 4.3 权限范围

| 范围 | 权限 |
| --- | --- |
| 民宿、房型公开列表和详情、房态、公开评价、推荐 | 游客可访问 |
| `/user/info`、收藏、购物车、用户评价 | USER |
| 订单 | USER 或 ADMIN，按资源所有权和状态操作限制 |
| 民宿/房型管理、用户管理、评价审核、看板、上传 | ADMIN |

## 5. 登录与用户

### 5.1 旧登录接口（已停用）

```http
POST /user/login?code=xxx
```

固定返回 `410`，请改用 `/user/wxlogin`。

### 5.2 微信登录

```http
POST /user/wxlogin
Content-Type: application/json
```

```json
{
  "code": "微信临时登录凭证",
  "agreed": true
}
```

`agreed` 不为 `true` 时返回 `400`。成功时返回 JWT、用户 ID 和用户基本信息。

### 5.3 当前用户信息

```http
GET /user/info
Authorization: Bearer <USER JWT>
```

### 5.4 修改当前用户信息

```http
POST /user/update
Authorization: Bearer <USER JWT>
Content-Type: application/json
```

可更新字段：`nickname`、`avatarUrl`、`gender`、`birthday`、`phone`、`email`。`birthday` 格式为 `yyyy-MM-dd`。

### 5.5 管理员查询用户

```http
GET /user/list?page=1&size=10&nickname=张&phone=138&status=1
Authorization: Bearer <ADMIN JWT>
```

筛选条件均参与查询；每个用户对象补充有效订单数 `orderCount`。

### 5.6 管理员查询用户订单

```http
GET /user/{userId}/orders?page=1&size=10
Authorization: Bearer <ADMIN JWT>
```

排除已取消和已退款订单。

### 5.7 修改用户状态

```http
PUT /user/{userId}/status
Authorization: Bearer <ADMIN JWT>
Content-Type: application/json
```

```json
{ "status": 0 }
```

`0` 为禁用，`1` 为启用。

## 6. 管理员

### 6.1 登录

```http
POST /api/admin/login?username=admin&password=admin123
```

账号从数据库读取，密码使用 BCrypt 校验。首次运行时会将遗留占位密码升级为配置项 `app.admin.initial-password` 指定的初始密码。

成功返回：

```json
{
  "code": 200,
  "msg": "登录成功",
  "data": {
    "token": "JWT",
    "adminId": 1,
    "role": "ADMIN"
  }
}
```

### 6.2 当前管理员信息

```http
GET /api/admin/info
Authorization: Bearer <ADMIN JWT>
```

## 7. 民宿

### 7.1 列表

```http
GET /homestay/list?page=1&size=10&keyword=西安&status=1
```

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| page | 否 | 从 1 开始 |
| size | 否 | 默认 10，最大 50 |
| keyword | 否 | 同时匹配名称和地址 |
| status | 否 | 仅管理员请求生效 |

游客只会得到 `status=1` 的民宿。管理员携带有效 Token 时可查询全部或按 `status` 筛选。列表项补充 `minPrice`。

### 7.2 详情

```http
GET /homestay/{id}
```

游客访问已下架民宿时返回 `404`，管理员可以查看。

### 7.3 管理接口

```http
POST   /homestay/create
PUT    /homestay/update/{id}
DELETE /homestay/delete/{id}
PUT    /homestay/toggleStatus/{id}
Authorization: Bearer <ADMIN JWT>
```

主要校验：名称 2～50 字符、地址 5～120 字符、描述最多 500 字符。删除民宿会先删除关联房型。

## 8. 房型

### 8.1 民宿下的房型列表

```http
GET /room/list?homestayId=1&page=1&size=10&keyword=大床&bedType=大床&priceRange=0-500
GET /room/list?scope=all&page=1&size=50
```

普通用户按民宿浏览时必须提供 `homestayId`；传入 `scope=all` 且不传 `homestayId` 时，返回全部上架、有库存且所属民宿已上架的房型，每项包含 `homestayId` 和 `homestayName`。非法 `scope` 不会放宽民宿限制。管理员请求可以不提供 `homestayId`，并可增加 `status` 参数。单次返回量最多 50 条。

### 8.2 综合搜索

```http
GET /room/search?keyword=大床&page=1&size=10
```

只返回已上架、有库存且所属民宿已上架的房型。

### 8.3 详情与公开评价

```http
GET /room/{id}
GET /room/{id}/reviews?page=1&size=10
```

详情会将 `gallery` 转为图片数组；公开评价只返回审核通过的数据。

### 8.4 房态日历

```http
GET /room/calendar?roomId=1&startDate=2026-09-20&endDate=2026-09-30
```

返回每日 `date`、`price`、`stock`、`status`。

### 8.5 管理接口

```http
GET    /room/count/{homestayId}
POST   /room/create
PUT    /room/update/{id}
DELETE /room/delete/{id}
PUT    /room/toggleStatus/{id}
Authorization: Bearer <ADMIN JWT>
```

房型请求主要字段：`homestayId`、`roomTypeId`、`name`、`description`、`price`、`originalPrice`、`area`、`bedType`、`peopleNum`、`stock`、`status`、`coverImage`、`gallery`。

校验规则：销售价大于 0、最多 10000 元且最多两位小数；原价不得低于销售价；库存为 0～999；描述最多 500 字符。

## 9. 订单

订单状态：`0` 待支付、`1` 已支付/已确认、`2` 已入住、`3` 已完成、`4` 已取消、`5` 已退款。

### 9.1 创建订单

```http
POST /order/create
Authorization: Bearer <USER JWT>
Content-Type: application/json
```

```json
{
  "roomId": 1,
  "checkInDate": "2026-09-20",
  "checkOutDate": "2026-09-22",
  "contactName": "张三",
  "contactPhone": "13800138000",
  "remark": "安静房间"
}
```

可选字段 `cartId` 用于从购物车结算。服务端根据房型和日期生成 `roomName`、`roomImage`、`nights`、`price`、`totalAmount`、`realAmount`、`orderNo`，并校验上下架、库存、房态和重叠订单。

日期规则：入住日不得早于当天，离店日必须晚于入住日，日期不得超过未来 365 天，最多入住 60 晚。备注最多 200 字符。

### 9.2 批量创建

```http
POST /order/batch-create
Authorization: Bearer <USER JWT>
```

```json
{
  "orders": [
    {
      "cartId": 10,
      "roomId": 1,
      "checkInDate": "2026-09-20",
      "checkOutDate": "2026-09-22",
      "contactName": "张三",
      "contactPhone": "13800138000",
      "remark": ""
    }
  ]
}
```

单次最多 10 项；仅成功下单的购物车项会被删除。

### 9.3 列表和详情

```http
GET /order/list?page=1&size=10&orderNo=ORD&contactName=张&status=0
GET /order/{id}
Authorization: Bearer <USER 或 ADMIN JWT>
```

用户只能查看本人订单，管理员可查看全部订单。

### 9.4 更新状态

```http
PUT /order/{id}/status
Authorization: Bearer <USER 或 ADMIN JWT>
Content-Type: application/json

{ "status": 1 }
```

兼容旧请求：

```http
PUT /order/{id}/status?status=1
```

合法流转：`0 -> 1/4`、`1 -> 2/4`、`2 -> 3`。用户只能对自己的待支付订单执行 `0 -> 1`；确认、入住和完成由管理员办理。

### 9.5 取消

```http
PUT /order/{id}/cancel
Authorization: Bearer <USER 或 ADMIN JWT>

{ "reason": "行程有变" }
```

仅状态 0 或 1 可以取消。

## 10. 购物车

以下接口均要求 USER JWT：

```http
POST /cart/add
PUT  /cart/{id}
POST /cart/remove
GET  /cart/list
POST /cart/clear
```

添加和修改日期请求体：

```json
{
  "roomId": 1,
  "checkInDate": "2026-09-20",
  "checkOutDate": "2026-09-22"
}
```

`PUT /cart/{id}` 不需要 `roomId`。删除请求体为 `{ "id": 10 }`。添加和修改均复用订单日期、库存和房态校验。

## 11. 收藏

以下接口均要求 USER JWT：

```http
POST /favorite/add       body: { "roomId": 1 }
POST /favorite/remove    body: { "roomId": 1 }
GET  /favorite/list
GET  /favorite/check?roomId=1
```

只能收藏已上架、有库存且所属民宿已上架的房型。

## 12. 评价

### 12.1 用户接口

```http
GET    /review/user?page=1&size=10&status=0
POST   /review/create
PUT    /review/{id}/update
DELETE /review/{id}/delete
Authorization: Bearer <USER JWT>
```

创建请求：

```json
{
  "orderId": 1001,
  "rating": 5,
  "content": "房间干净，体验很好",
  "images": ["/images/review-1.jpg"]
}
```

仅本人已完成且未评价的订单可评价。评分为 1～5，内容为 1～500 字符。只有状态 2（审核驳回）的评价可以修改，修改后重置为状态 0（待审核）。

### 12.2 公开详情

```http
GET /review/{id}
```

### 12.3 管理员接口

```http
GET  /review/list?page=1&size=10&roomName=大床&status=0
GET  /review/{id}/detail
POST /review/{id}/approve
POST /review/{id}/reject    body: { "reason": "内容不符合规范" }
Authorization: Bearer <ADMIN JWT>
```

评价状态：`0` 待审核、`1` 已通过、`2` 已驳回。

## 13. 推荐

```http
GET /recommend/rooms?size=8&alpha=0.6
```

Token 可选。`size` 限制为 1～20，`alpha` 限制为 0～1。只推荐已上架民宿下有库存的上架房型。

## 14. 图片上传与访问

```http
POST /upload/image
Authorization: Bearer <ADMIN JWT>
Content-Type: multipart/form-data
```

表单字段：`file`。支持 JPG/JPEG、PNG、WEBP，MIME 类型必须与扩展名匹配，单文件最大 5 MB。

成功返回：

```json
{
  "code": 200,
  "msg": "上传成功",
  "data": {
    "url": "/images/uuid.png",
    "imageUrl": "/images/uuid.png"
  }
}
```

图片可通过以下地址访问：

```text
http://127.0.0.1:8082/images/uuid.png
```

## 15. 数据看板

全部要求 ADMIN JWT：

```http
GET /dashboard/test
GET /dashboard/stats
GET /dashboard/income-trend?period=7day
GET /dashboard/room-type-distribution
GET /dashboard/latest-orders
GET /dashboard/pending-tasks
```

`period` 支持 `7day`、`30day`。

## 16. 已移除接口

V1.1 已移除旅游资讯 Controller，以下接口返回 `404`：

```text
/news/list
/news/{id}
/news/create
/news/update
/news/delete
```

数据库中的历史资讯表可以保留，但小程序、后台和后端不再提供资讯业务入口。

## 17. 核心调用示例

查询民宿：

```bash
curl "http://127.0.0.1:8082/homestay/list?page=1&size=10"
```

管理员登录：

```bash
curl -X POST "http://127.0.0.1:8082/api/admin/login?username=admin&password=admin123"
```

创建订单：

```bash
curl -X POST "http://127.0.0.1:8082/order/create" \
  -H "Authorization: Bearer <USER JWT>" \
  -H "Content-Type: application/json" \
  -d '{
    "roomId": 1,
    "checkInDate": "2026-09-20",
    "checkOutDate": "2026-09-22",
    "contactName": "张三",
    "contactPhone": "13800138000",
    "remark": ""
  }'
```

管理员确认订单：

```bash
curl -X PUT "http://127.0.0.1:8082/order/1001/status" \
  -H "Authorization: Bearer <ADMIN JWT>" \
  -H "Content-Type: application/json" \
  -d '{"status":1}'
```
