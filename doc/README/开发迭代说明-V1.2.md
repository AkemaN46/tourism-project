# 汐岸小筑民宿平台 V1.2 开发迭代说明

**发布日期：** 2026-09-19  
**面向对象：** 小程序、后端开发与测试人员  
**版本目标：** 在 V1.1 回归通过的基础上，完成首页“为你推荐”模块的“查看更多”入口，支持用户浏览全部可售房型。

## 1. 版本范围

V1.1 已修复和关闭的内容不再纳入本期开发。V1.2 仅实现以下一项功能：

| 编号 | 功能 | 优先级 | 状态 |
| --- | --- | --- | --- |
| V1.2-F01 | 首页“为你推荐”增加“查看更多”入口，并进入全局房型列表 | P1 | 已完成，回归通过 |

本期不重新实现资讯、首页快捷入口、底部订单导航、民宿列表、民宿详情、订单与权限校验、图片上传及输入边界等 V1.1 已完成内容。

### 1.1 遗留缺陷处理声明

以下事项不纳入 V1.2-F01，不得在本次开发中顺带改动：

| 处理结论 | BUG 编号 | 产品说明 |
| --- | --- | --- |
| 关闭（产品决策） | BUG-016、BUG-017、BUG-022 | 当前业务规则为“一笔订单对应一间房”；购物车不提供房间数量修改。小程序端的购物车、收藏列表不采用分页、触底加载或“加载更多”。 |
| 计划 V1.3 | BUG-015、BUG-021、BUG-027、BUG-029、BUG-031、BUG-032、BUG-033、BUG-035、BUG-038 | 购物车、收藏及后台民宿、房型、订单、评价、用户模块的批量管理能力，属于运营效率优化，不阻塞当前用户浏览、下单和订单主链路。后续作为“批量操作能力”需求包统一评审、排期和验收。 |

本次仅交付 V1.2-F01；上述 V1.3 事项在需求评审完成前不得以“修复缺陷”名义插入本版本。

## 2. 功能需求

### 2.1 首页入口

在首页“为你推荐”标题右侧增加文字按钮“查看更多 >”。

- 仅当推荐房型列表有数据时显示该标题及入口。
- 点击“查看更多 >”后进入“全部房型”页面。
- 点击推荐卡片本身仍进入对应房型详情，现有行为不得改变。
- 推荐卡片继续显示房型名称、所属民宿名称、价格和封面图。

### 2.2 全部房型页面

复用 `pages/room/list` 页面，新增 `scope=all` 页面参数。

| 场景 | 页面标题 | 数据范围 | 页面要求 |
| --- | --- | --- | --- |
| 从某民宿进入 | `{民宿名称} · 房型` | 仅该民宿的可售房型 | 保留民宿头部信息与筛选能力。 |
| 从“为你推荐 → 查看更多”进入 | `全部房型` | 全部可售房型 | 不展示某一家民宿的头部信息；每张房型卡片必须展示“所属民宿：{民宿名称}”。 |

“全部可售房型”必须同时满足：

- 房型状态为上架；
- 所属民宿状态为上架；
- 房型库存大于 0；
- 房型封面图可用；无可用图片时显示项目内置占位图，不隐藏房型卡片。

用户点击全局房型卡片时，进入对应房型详情。房型详情、收藏、加购和预订权限沿用 V1.1 现有规则。

## 3. 接口与前端实现要求

### 3.1 后端接口

当前 `/room/list` 在普通用户未传 `homestayId` 时返回“请先选择民宿后再查看房型”。V1.2 需要支持全局可售房型查询。

建议复用 `GET /room/list`，新增可选参数 `scope=all`：

| 请求方式 | 参数 | 返回要求 |
| --- | --- | --- |
| 民宿内房型 | `homestayId={id}` | 保持 V1.1 现有行为。 |
| 全部房型 | `scope=all`，不传 `homestayId` | 返回全部可售房型，且每一项包含 `id`、`name`、`coverImage`、`price`、`stock`、`homestayId`、`homestayName`。 |

全局查询不得返回下架民宿、下架房型或库存为 0 的房型。接口仍需限制单次返回量不超过 50 条；本期小程序不展示分页或“加载更多”。

### 3.2 小程序实现

1. 在 `pages/index/index.wxml` 的“为你推荐”标题区增加“查看更多 >”按钮。
2. 在 `pages/index/index.js` 增加跳转函数，使用 `wx.navigateTo` 打开：

   ```text
   /pages/room/list?scope=all
   ```

3. 在 `pages/room/list.js` 的 `onLoad` 中识别 `scope=all`：

   - 全局模式不执行“未选择民宿则跳转民宿列表”的逻辑；
   - 全局模式请求 `/room/list` 时带 `scope=all`，不传 `homestayId`；
   - 页面标题设置为“全部房型”；
   - 不加载民宿头部信息；
   - 卡片展示所属民宿名称。

4. 民宿内房型模式仍必须要求 `homestayId`，不得因新增全局模式而放宽或混淆原有页面路径。
5. 全局房型、民宿内房型和首页推荐均使用一次性完整列表加载方式；不新增分页、触底加载或“加载更多”。

## 4. 异常与空态

| 场景 | 页面表现 |
| --- | --- |
| 全部房型接口成功但无可售数据 | 显示“暂无可售房型”。 |
| 网络或接口请求失败 | 显示“加载失败，点击重试”；不得显示为“暂无可售房型”。 |
| 图片加载失败 | 使用项目内置占位图，房型信息和点击行为保持可用。 |
| `scope` 参数非法 | 按民宿内房型逻辑处理；未携带有效 `homestayId` 时返回民宿列表，不得展示未过滤的房型。 |
| 房型或所属民宿在进入详情前已下架 | 详情页显示资源不可用提示并返回上一页，不允许继续下单。 |

- [x] 全部房型页展示全部可售房型，每张卡片显示所属民宿名称、房型名称、价格和封面图。
- [x] 下架民宿、下架房型和库存为 0 的房型不出现在全部房型页。
- [x] 点击任一房型可进入正确详情；详情、收藏、加购和预订行为不受影响。
- [x] 从民宿详情进入房型页时，仍只展示该民宿的房型并保留原民宿头部信息。
- [x] 全局房型页、民宿内房型页和首页推荐页均不出现分页、触底加载或“加载更多”。
- [x] 无数据、接口失败和图片失败三种状态分别按第 4 节展示，页面不白屏、不误报空数据。

## 6. 测试要求

开发提交前至少完成以下验证：

1. 新增至少 2 家上架民宿，每家配置 2 个上架且有库存的房型，验证全局房型页共展示 4 个房型，并显示正确所属民宿。
2. 分别将民宿下架、房型下架、库存改为 0，验证对应房型从全局房型页消失。
3. 验证从首页推荐、查看更多、民宿详情三条路径均可进入正确房型详情。
4. 验证接口异常和图片异常时的页面提示与占位图表现。
5. 运行 V1.1 已有订单、收藏、购物车和房型详情核心回归，确认本次路由与列表改造未产生回归。
